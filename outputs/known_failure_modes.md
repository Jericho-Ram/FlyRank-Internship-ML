# Known Failure Modes

Hand-maintained. Not generated by `scripts/04_evaluate_and_export.py`.
Each entry names a condition under which the score should not be trusted, and what was done about it.

## 1. Zero-click pages cannot decline, and they are most of the data

`107,900` of the warehouse rows (`61.1%`) have `clicks_mar == 0`, and their
declining rate is exactly `0.000` — April clicks cannot fall below zero.
Scoring them inflates AUC from `0.576` to `0.901` without predicting anything.

**Fix.** Score only pages where decline is arithmetically possible (`38.9%`).
Pages with no March clicks are routed to a separate question — is this page
visible at all — which is a different product.

**Don't trust the score when** the scored population has not been filtered this way.

## 2. The 90-day query window opens inside the label month

`fact_content_query_90d` has `window_start = 2026-04-02` and
`window_end = 2026-06-30`. A decision made on 1 April cannot use it.
This was assumed and then measured in Test E of `w03_feature_leakage_check.ipynb`.

**Fix.** A guard that refuses to run if the feature window's end date falls on or
after the label window's start date. Assume nothing about a window; read it.

**Don't trust the score when** any feature table's window has not been read directly.

## 3. GA4 features are 59% missing, and missing for the wrong reason

`sessions_mar`, `engagement_rate_mar`, `scroll_per_session_mar` and `ai_share_mar`
are absent because a client had no GA4 in March, not because the page had no
engagement. Kept, with `ga4_usable` as a `0/1` flag so the model can separate
the two, and median imputation inside the fold.

**Fix.** Check per-fold feature importance before shipping. If it concentrates on
GA4 columns, the model is likely using GA4 presence as a client fingerprint
rather than an engagement signal.

**Don't trust the score when** importance sits on GA4 columns and clients differ
in GA4 coverage.

## 4. Open — the bundled CSV metrics predate the zero-click finding

Precision@50 of `0.240` (hand rule) and `0.680` (random forest) were measured on
the bundled `30,000`-row CSV, before Test D. The zero-click partition has not
been run on that slice. Test E found the CSV's label was probably derived from
the same 30-day click pair as `fact_content_query_90d`, so the same mechanism
may apply.

**Status.** Untested, not disproven. Quoted with this note attached until re-run.
